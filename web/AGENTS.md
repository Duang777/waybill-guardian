# web · AGENTS.md

## 职责

React 运营控制台。目标是在三分钟内显示异常、归因、审批、平台写入和审计回放。
页面不持有业务权威状态，所有 run 和审批状态都从 HTTP 响应及 SSE 事件投影。

## 页面结构

1. 经营总览 `/`：显示 6 项经营 KPI、全国港网、风险队列、3 张经营图表和带统计引用的只读经营简报。
2. 批量处置：从风险队列选择运单后调用 `/api/runs:batch`，再按 run 打开 SSE。
3. 单运单工作台 `/waybills/:id`：按案件桌案展示运单摘要、运行阶段、空间证据、人工决策和审计回放。
4. 城市配送调度台 `/delivery/plans/:revisionID`：展示路线、司机时间轴、SOC、逐站 3D
   装卸、独立校验、审批 effect 和计划审计。

## 设计决策

- 高德 key 存在时加载高德 JS API。key 缺失或 SDK 加载失败时，`RouteMap` 显示不含行政边界
  的本地轨迹示意。OpenFreeMap 只在 `VITE_VECTOR_MAP=openfreemap` 时启用。
- `timelineReducer` 是页面状态的唯一入口。它按 `seq` 排序并忽略重复事件。
- 浏览器原生 `EventSource` 负责重连和 `Last-Event-ID`。服务端按该游标补齐事件。
- 目录、运单详情和 run 分别建模。启动后以响应中的 `waybill_id` 为权威值。
- 切换运单或 run 会中止旧请求并递增选择代次，旧响应不能覆盖新页面。
- 启动恢复优先选择待审批 run，其次选择其他活跃 run；页面恢复不会隐式创建 run。
- 经营总览首次加载 active run，之后每 2 秒发现其他客户端启动的 run。每个 run 仍通过 SSE
  推进状态，前端按 `last_seq` 忽略旧摘要和旧事件。
- 审批操作进行时禁用按钮。驳回必须先填写原因。
- API 响应通过 Zod 在边界解析。结构不符合契约时，页面显示错误。
- Delivery 调度台只接受 `delivery.workspace.v1` read model。它复验 revision 和
  problem/policy/commitment/plan digest 绑定，并拒绝悬空车辆、位置、任务、货物、舱室和门引用。
- Delivery 路线、司机时间轴、SOC 和装载阶段由同一个离散 stop 游标驱动。浏览器只投影
  artifact，不补算路线、装载坐标、校验结论或收益。
- Delivery 3D 装载静止时使用 `frameloop="demand"`，超过 100 件货物切换
  `InstancedMesh`。WebGL 不可用或 context 丢失时显示同一 placement 数据生成的顶视 SVG。
- API 边界将非法 JSON、契约不符、无权限、超时和服务不可用映射为独立状态；加载态使用
  与最终网格同尺寸的骨架，空目录不显示业务兜底数据。
- 工作台区分 SSE 连接中、在线、重连中、浏览器离线和审计已固化。待审批 run 只有在
  SSE 在线时允许确认或驳回；断线期间保留方案并锁定写操作。
- 地图、证据账本、人工决策和审计记录各有面板级错误边界，单个面板渲染失败不拖垮整页。
- 经营简报只展示 `/api/overview` 返回的聚合事实和引用，前端不直接调用模型，也不触发写操作。
- 经营图表只展示接口可证明的当前快照：异常构成、当前处置状态和高异常占比线路。接口没有
  历史桶、上期快照或人工基线时，不生成趋势、环比或漏斗。`delay_heat` 表示线路异常占比，
  不表示延误时长。
- ECharts 只从 `OverviewEChart.tsx` 动态加载，使用按需注册的 CanvasRenderer。每张图保留
  可见的精确值列表，独立处理空态和渲染失败，并在减少动态效果时关闭初始及更新动画。
- 视口至少为 1560×800 时，总览使用两行运营网格，在一屏内显示港网、队列、3 张图表和
  经营简报；单运单工作台使用
  “摘要 → 六阶段运行带 → 地图与证据账本 → 全宽人工决策闸 → 审计抽屉”的四层桌案。
  地图是空间证据，不充当页面背景；审批不是侧栏卡片。完整审计记录只在底部按需展开。
- 点击证据账本中的引用时，页面同时聚焦轨迹点并展开审计抽屉，定位到对应事件。
- Motion 只用于同一 run 的实时事件入场、审批状态交接和轨迹点详情反馈。共享时长为
  120/180/240ms；回放、首屏 hydration 和历史终态不误播，系统减少动态效果时不产生位移或缩放。
- 轨迹点详情使用浅色横向事实条。单运单页不得恢复黑色详情栏、永久 Agent 右栏或循环等待动画。
- 桌面决策闸横向展示方案、候选项和待执行动作；窄屏改为单列，待审批操作保持在可触达位置。
- 页面在 375 和 320 像素宽度下没有横向溢出，交互控件至少为 40 像素。

## 配置

- `VITE_API_TARGET`：Vite 开发代理的 API 地址，默认 `http://127.0.0.1:8080`。
- `VITE_AMAP_KEY`：可选的高德浏览器端 key。
- `VITE_AMAP_SECURITY_JS_CODE`：使用新版高德安全配置时填写。
- `VITE_VECTOR_MAP`：可选。仅值为 `openfreemap` 时启用外部矢量底图。

将高德配置写入 `web/.env.local`。该文件不提交。

## 验证

`npm test` 覆盖 API 边界、恢复优先级、时间线去重、审批投影、run 状态和回放 reducer。
`npm run verify:e2e`
使用 Chrome 连续确认三次演示，并验证一次驳回路径。脚本保存 desktop 和 mobile 截图，
检查四层桌案几何关系、本地轨迹、异常后节点状态、非法 URL、横向溢出、跳转链接和按钮尺寸。

`npm run verify:file-e2e` 使用双运单 CSV 启动 `PLATFORM=file`，验证目录切换、旧响应抑制、
动态路线和异常标签，以及所选运单的完整审批执行。

`npm run verify:overview` 使用 72 港仿真数据验证 6 项 KPI、3 张非空经营图表、港网 SVG、
5 个独立 run 与审批、
外部 run 的首次恢复和自动发现、单独确认不影响其余 4 个审批、地图下钻、轨迹异常点，以及
1920、1600、1560×800、1440、1280、375 和 320 像素宽度的响应式布局，并要求首屏 CLS
小于 0.1。生产构建还运行图表 bundle 门禁，要求完整动态图表块 gzip 小于 350 KB。

`npm run verify:states` 在隔离浏览器中覆盖后端停止、HTTP 500、非法 JSON 和空目录四种状态，
并验证 375 像素空状态无横向溢出、不会请求或渲染固定业务兜底数据。

`npm run verify:motion` 使用真实 Chrome 采样实时事件、审批终态和快速轨迹选点的
transform/opacity，动态切换 reduced-motion 后要求无位移，并保存桌面、375/320 和选点帧。
生产构建同时要求入口 gzip 相对 `187686` 字节基线增长小于 25 KB。

`npm run verify:delivery` 用版本化 API fixture 验证调度台 WebGL 像素、路线与装载联动、
键盘步骤切换、context 丢失后的 SVG 降级、审批按钮命中区、375 像素无横向溢出和契约错误态。
脚本保存桌面与手机完整截图。

`npm run record:demo` 默认使用在线模型，启动隔离服务并录制确认、回放和驳回路径，再用
ffmpeg 生成带中文字幕的 MP4。默认分辨率是 1600×900；正式高清录制可设置
`RECORD_RESOLUTION=1920x1080`。无模型凭据时显式运行
`AGENT_MODE=offline npm run record:demo`。录制文件写入已忽略的 `web/artifacts/`。
