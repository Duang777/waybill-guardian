# 3 分钟演示讲稿

## 录制前准备

1. 按 [`README.md`](../README.md#在线模型) 配置 `LLM_API_STYLE`、`LLM_BASE_URL`、`LLM_API_KEY` 和 `LLM_MODEL`。
2. 运行 `./scripts/demo.sh`。
3. 打开 <http://127.0.0.1:5173>。
4. 保持浏览器缩放为 100%，并确认页面显示运单 `YD2026101001`。
5. 清空通知和其他可能遮挡页面的窗口。

正式演示和录像默认调用在线模型。无模型凭据排练时，运行
`AGENT_MODE=offline ./scripts/demo.sh`。没有高德密钥时，本地轨迹视图仍显示完整路线、
异常点和点位详情。

仓库也提供无音轨的字幕版录制：

```bash
cd web
npm run record:demo
```

录像脚本继承模型配置。无凭据试录时，运行
`AGENT_MODE=offline npm run record:demo`。输出文件是
`web/artifacts/waybill-guardian-demo.mp4`。正式提交前，按下文口述稿补充配音，并检查赛事
平台对时长、分辨率和文件大小的限制。

脚本默认录制 1600×900。需要 1920×1080 正式高清版本时运行：

```bash
RECORD_RESOLUTION=1920x1080 npm run record:demo
```

## 逐字稿

### 00:00 至 00:20

操作：停留在控制台首屏。

口述：

> 这是 Waybill Guardian，一套异常运单处置 Agent。它自动调查异常、生成处置方案，
> 但不能自行修改 TMS 或发送通知。每个写操作都必须先经过人工审批。

### 00:20 至 00:40

操作：依次指向紧凑运单摘要、六阶段运行带、地图与证据账本、全宽人工决策闸和底部审计入口。

口述：

> 当前运单从杭州发往成都，运输的是精密电子元件。页面把运营人员需要的信息放在同一屏：
> 上方是运单和风险，下面依次是运行阶段、地图与证据账本、人工决策闸。地图只负责空间
> 证据，写操作单独横跨全宽；完整审计记录需要时再从底部展开。

### 00:40 至 01:10

操作：在运单目录中保留默认运单，点击 **启动处置**，等待审批卡片出现。

口述：

> 启动后，Agent 依次查询运单、轨迹、司机和沿途天气。每次工具调用和返回都会先写入
> append-only 审计日志，再通过 SSE 推送到页面。这里发现司机连续驾驶九小时，
> 车辆在绵阳北服务区停留六小时，同时天气晴朗且没有预警。因此系统排除了天气因素，
> 把延误归因到疲劳驾驶和异常停留。

### 01:10 至 01:45

操作：指向六阶段运行带、证据账本，以及人工决策闸中的审批方案、待执行动作和有效期。

口述：

> Agent 现在提出第一版方案，页面列出模型选择的承运商、排序依据，以及货主和司机通知。注意，三个写操作还没有执行。
> hastekit 在工具调用前暂停 run，服务端根据业务参数生成每项 effect 身份，再把参数和证据组成审批批次。
> 审批人看到完整影响后才能决定。

### 01:45 至 02:10

操作：点击 **确认并执行**，等待状态变为 **处置完成**。

口述：

> 我现在确认。服务端先持久化人工决定，再恢复同一个 hastekit thread。写操作通过 effect 身份
> 校验后才到达平台。即使模型重试、页面重复点击或服务恢复，相同业务 effect 也只执行一次。
> 底部审计记录现在包含 TMS 改派、两条短信通知和 run 完成。

### 02:10 至 02:30

操作：展开 **完整审计记录**，点击回放按钮，观察事件从第一条开始播放，再点击 **实时**。

口述：

> 审计不是页面临时状态。每个事件都有连续序号、前序哈希和当前哈希。回放直接读取持久化日志，
> SSE 断线后也能从最后一个事件序号继续。

### 02:30 至 02:52

操作：点击 **重新处置**。审批出现后点击 **驳回方案**，填写
`首选承运商当前无可用车辆`，再点击 **确认驳回**。等待页面显示第二版改派方案。

口述：

> 人工也可以驳回方案，并且必须填写原因。驳回决定会恢复 Agent，而不是直接结束流程。
> Agent 读取决定后提交第二个候选运力。超时未处理时，系统同样按拒绝处理，不会默认放行。

### 02:52 至 03:00

操作：停留在第二版审批卡片，保持底部审计记录展开。

口述：

> 这套实现把自动调查、人类决策、幂等写入和可回放审计放进一条完整链路。默认数据可重复演示，
> 接入真实平台时只替换 platform adapter。

## 录制后检查

- 视频包含启动、归因、确认、一次 TMS 改派、两条短信通知和完成状态。
- 视频包含驳回原因和第二候选方案。
- 审批前没有 `write_started` 或 `write_executed` 事件。
- 视频分辨率是 1600×900 或 1920×1080，画面没有页面级纵向滚动。
- 画面没有密钥、手机号原文、终端用户名或本地绝对路径。
- 仓库链接指向公开仓库：<https://github.com/Duang777/waybill-guardian>。
