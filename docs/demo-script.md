# 3 分钟演示讲稿

## 录制前准备

1. 运行 `./scripts/demo.sh`。
2. 打开 <http://127.0.0.1:5173>。
3. 保持浏览器缩放为 100%，并确认页面显示运单 `YD2026101001`。
4. 清空通知和其他可能遮挡页面的窗口。

默认演示不需要模型密钥或高德密钥。没有高德密钥时，本地轨迹视图仍显示完整路线、
异常点和点位详情。

## 逐字稿

### 00:00 至 00:20

操作：停留在控制台首屏。

口述：

> 这是 Waybill Guardian，一套异常运单处置 Agent。它自动调查异常、生成处置方案，
> 但不能自行修改 TMS 或发送通知。每个写操作都必须先经过人工审批。

### 00:20 至 00:40

操作：依次指向运单摘要、风险评分、异常轨迹、审计时间线和人工决策区。

口述：

> 当前运单从杭州发往成都，运输的是精密电子元件。页面把运营人员需要的信息放在同一屏：
> 上方是运单和风险，左侧是轨迹与审计，右侧是人工决策。

### 00:40 至 01:10

操作：点击 **启动演示**，等待审批卡片出现。

口述：

> 启动后，Agent 依次查询运单、轨迹、司机和沿途天气。每次工具调用和返回都会先写入
> append-only 审计日志，再通过 SSE 推送到页面。这里发现司机连续驾驶九小时，
> 车辆在绵阳北服务区停留六小时，同时天气晴朗且没有预警。因此系统排除了天气因素，
> 把延误归因到疲劳驾驶和异常停留。

### 01:10 至 01:45

操作：指向审批卡片中的方案、待执行动作、证据链和有效期。

口述：

> Agent 现在提出第一版方案：改派到川行快运，并通知货主。注意，两个写操作还没有执行。
> hastekit 在工具调用前暂停 run，服务端把原始参数、证据和幂等键组成一个审批批次。
> 审批人看到完整影响后才能决定。

### 01:45 至 02:10

操作：点击 **确认并执行**，等待状态变为 **处置完成**。

口述：

> 我现在确认。服务端先持久化人工决定，再恢复同一个 hastekit thread。写操作通过审批校验和
> 幂等校验后才到达平台。即使模型重试、页面重复点击或服务恢复，相同业务 effect 也只执行一次。
> 时间线现在显示 TMS 改派、短信通知和 run 完成。

### 02:10 至 02:30

操作：点击回放按钮，观察时间线从第一条事件开始播放，再点击 **实时**。

口述：

> 审计不是页面临时状态。每个事件都有连续序号、前序哈希和当前哈希。回放直接读取持久化日志，
> SSE 断线后也能从最后一个事件序号继续。

### 02:30 至 02:52

操作：点击 **重新演示**。审批出现后点击 **驳回方案**，填写
`首选承运商当前无可用车辆`，再点击 **确认驳回**。等待页面显示 **改派至蜀道联运**。

口述：

> 人工也可以驳回方案，并且必须填写原因。驳回决定会恢复 Agent，而不是直接结束流程。
> Agent 读取决定后提交第二个候选运力。超时未处理时，系统同样按拒绝处理，不会默认放行。

### 02:52 至 03:00

操作：停留在第二版审批卡片和审计时间线。

口述：

> 这套实现把自动调查、人类决策、幂等写入和可回放审计放进一条完整链路。默认数据可重复演示，
> 接入真实平台时只替换 platform adapter。

## 录制后检查

- 视频包含启动、归因、确认、两次写入和完成状态。
- 视频包含驳回原因和第二候选方案。
- 审批前没有 `write_started` 或 `write_executed` 事件。
- 画面没有密钥、手机号原文、终端用户名或本地绝对路径。
- 仓库链接指向公开仓库：<https://github.com/Duang777/waybill-guardian>。
